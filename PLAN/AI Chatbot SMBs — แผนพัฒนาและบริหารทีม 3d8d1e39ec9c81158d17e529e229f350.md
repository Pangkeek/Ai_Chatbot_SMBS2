## รายละเอียดแต่ละงาน

ทำตามลำดับโดยรวม งานหน้าจอเริ่มจากข้อมูลจำลองได้เมื่อรูปแบบ API ตกลงกันแล้ว ก่อนเปลี่ยนเป็น “เสร็จแล้ว” ให้อีกคนลองใช้งานและตรวจผล

### 1. ตกลงขอบเขตและศึกษาพื้นฐาน

**ทำอะไร:** สรุปว่าจะทำอะไรบ้างและเข้าใจหลักการก่อนเริ่มเขียนระบบ

**ทำยังไง:** อ่านขอบเขตในรายงานร่วมกัน เลือก LINE Text เป็นช่องทางแรก ศึกษา IR, Embedding, Similarity, Transformer และ RAG แล้วลองค้นคำตอบจากข้อมูลร้านตัวอย่าง

**เสร็จเมื่อ:** มีรายการฟีเจอร์ที่ตกลงกัน แบบหน้าจอคร่าว ๆ และตัวอย่างคำถามพร้อมคำตอบที่ถูกต้อง

### 2. วางโครงสร้างระบบและฐานข้อมูล

**ทำอะไร:** เตรียมโครงการให้ทั้งทีมเริ่มพัฒนาต่อได้

**ทำยังไง:** สร้าง repository และวิธีรัน ออกแบบตารางผู้ใช้ ร้านค้า ความรู้ บทสนทนาและข้อความ กำหนดรูปแบบ API ร่วมกับศุภวัฒน์ และเตรียมข้อมูลทดสอบ 2 ร้าน

**เสร็จเมื่อ:** ทั้งสองคนรันโครงการได้ มี ERD และ API ที่ตกลงตรงกัน

### 3. ทำสมัครสมาชิก เข้าสู่ระบบ และแยกข้อมูลร้าน

**ทำอะไร:** ให้แต่ละร้านมีบัญชีและเข้าถึงเฉพาะข้อมูลของตัวเอง

**ทำยังไง:** ทำระบบบัญชีและ session ผูกข้อมูลกับ tenant_id ตรวจสิทธิ์ทุกครั้งที่อ่านหรือแก้ข้อมูล ศุภวัฒน์ช่วยทำหน้าสมัครและล็อกอิน

**เสร็จเมื่อ:** สมัครและล็อกอินได้ และใช้บัญชีร้านหนึ่งเปิดข้อมูลอีกร้านไม่ได้

### 4. ทำหน้าตั้งค่าธุรกิจ

**ทำอะไร:** ให้เจ้าของร้านตั้งค่าข้อมูลที่บอทต้องใช้

**ทำยังไง:** ทำฟอร์มชื่อร้าน เวลาเปิดปิด สินค้า บริการ และบุคลิกการตอบของบอท เชื่อม API สำหรับบันทึกและแก้ไข พร้อมแจ้งเมื่อกรอกข้อมูลไม่ครบ

**เสร็จเมื่อ:** บันทึกแล้วเปิดกลับมาได้ค่าตรงเดิม และเปลี่ยนเฉพาะร้านของผู้ใช้

### 5. เชื่อม LINE และจัดเก็บข้อความ

**ทำอะไร:** รับข้อความจากลูกค้า ส่งคำตอบกลับ และเก็บประวัติ

**ทำยังไง:** ตั้งค่า LINE channel กับ webhook ตรวจคำขอ แยกงานตอบออกไปประมวลผลใน worker เก็บ Conversation/Message และใช้รหัสเหตุการณ์กันการรับซ้ำ

**เสร็จเมื่อ:** ส่งข้อความ LINE จริงแล้วรับ–ตอบได้ มีประวัติถูกห้องและถ้าส่งเหตุการณ์ซ้ำไม่ตอบซ้ำ

### 6. ทำหน้าจัดการ FAQ และข้อมูลความรู้

**ทำอะไร:** ให้ร้านเพิ่มข้อมูลสำหรับตอบคำถามได้เอง

**ทำยังไง:** ทำหน้าเพิ่ม แก้ไข ลบ FAQ และข้อความเกี่ยวกับสินค้า/บริการ เชื่อม API ของสรวิชญ์ แสดงว่าข้อมูลพร้อมให้บอทใช้หรือยัง

**เสร็จเมื่อ:** ร้านแก้ข้อมูลได้และเมื่อประมวลผลเสร็จ บอทใช้ข้อมูลล่าสุดแทนข้อมูลเก่า

### 7. ทำระบบค้นข้อมูลและตอบด้วย RAG

**ทำอะไร:** ให้ AI ตอบโดยอ้างอิงข้อมูลของร้าน

**ทำยังไง:** แบ่งข้อความความรู้เป็นส่วนย่อย สร้าง embedding ค้นส่วนที่เกี่ยวข้องโดยกรองร้านก่อน แล้วส่งบริบทให้ AI ใช้ FAQ ที่ตรงคำถามได้โดยตรง หากไม่มีข้อมูลพอให้แจ้งว่าไม่ทราบหรือขอส่งต่อ

**เสร็จเมื่อ:** คำถามตัวอย่างได้คำตอบตรงแหล่งข้อมูล ระบุข้อมูลที่ใช้ตรวจย้อนหลังได้ และไม่มีข้อมูลข้ามร้าน

### 8. เชื่อม AI หลัก–สำรองและรองรับข้อผิดพลาด

**ทำอะไร:** ให้ระบบใช้ Gemini เป็นหลักและ OpenAI สำรองตามขอบเขตรายงาน

**ทำยังไง:** ทำตัวกลางเรียก AI ทั้งสองราย กำหนด timeout จำนวน retry และเวลารอที่เพิ่มขึ้น ใช้ Circuit Breaker หยุดเรียกบริการที่ล้มซ้ำ แล้วลองเส้นทางสำรอง

**เสร็จเมื่อ:** จำลองบริการหลักล้มแล้วยังตอบผ่านสำรองได้ ถ้าทั้งคู่ล้มระบบแจ้งหรือส่งต่อได้โดยไม่วนค้าง

### 9. ทำหน้าบทสนทนาและสถิติ

**ทำอะไร:** ให้แอดมินเปิดดูสิ่งที่ลูกค้าคุยกับบอทและติดตามการใช้งาน

**ทำยังไง:** ทำรายการห้องสนทนา หน้าข้อความ และสถานะบอท เชื่อม API ประวัติและสถิติ แสดงจำนวนข้อความ บทสนทนา และการส่งต่อแอดมินแยกตามร้าน

**เสร็จเมื่อ:** ประวัติตรงกับข้อความ LINE และตัวเลขสถิติตรงกับข้อมูลทดสอบ

### 10. ทำแอดมินรับช่วงตอบและหยุด–เปิดบอท

**ทำอะไร:** ให้มนุษย์เข้าควบคุมเมื่อบอทตอบไม่ได้หรือลูกค้าต้องการแอดมิน

**ทำยังไง:** ศุภวัฒน์ทำปุ่มรับช่วง พิมพ์ตอบ และ Pause/Resume; สรวิชญ์ทำสถานะฝั่งระบบ ตรวจโหมดก่อนส่งคำตอบทุกครั้ง รวมถึงคำตอบ AI ที่กำลังประมวลผลค้างอยู่

**เสร็จเมื่อ:** แอดมินตอบผ่าน LINE ได้ บอทไม่ตอบแทรกขณะพัก และกลับมาทำงานเมื่อ Resume

### 11. ทดสอบรวมและแก้บั๊ก

**ทำอะไร:** ตรวจว่าระบบครบเส้นทางและวัดคุณภาพได้จริง

**ทำยังไง:** ศุภวัฒน์ทดสอบหน้าจอและให้คะแนนคำตอบเทียบเฉลย; สรวิชญ์ทดสอบแยกร้าน ข้อความซ้ำ เวลาตอบ และ AI ล้มเหลว ทั้งคู่ทดสอบ Handover เก็บผลกับค่าใช้จ่าย แล้วแก้บั๊กและลองเคสที่ล้มซ้ำ

**เสร็จเมื่อ:** ฟีเจอร์หลักผ่าน ไม่มีบั๊กวิกฤตค้าง และมีผลทดสอบจริงเรื่องความถูกต้อง ความเกี่ยวข้อง การตอบไร้หลักฐาน ความเร็ว Handover และ Failover

### 12. นำขึ้นระบบ ทำรายงาน และเตรียมสาธิต

**ทำอะไร:** เตรียมต้นแบบที่เปิดใช้งานและอธิบายต่ออาจารย์ได้

**ทำยังไง:** สรวิชญ์นำเวอร์ชันที่ผ่านทดสอบขึ้นระบบสาธิตและเขียนวิธีติดตั้ง/สำรอง/กู้คืน; ศุภวัฒน์รวมรายงาน ผลทดลอง ข้อจำกัด และตรวจอ้างอิง ทั้งคู่ซ้อม Demo ตั้งแต่ตั้งร้านจนตอบ LINE และรับช่วงโดยแอดมิน

**เสร็จเมื่อ:** มีลิงก์ต้นแบบ คู่มือ รายงาน และ Demo ที่ทั้งสองคนสาธิตตามได้

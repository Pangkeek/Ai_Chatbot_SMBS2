# บทสนทนาและสถิติ — งานข้อ 9

## วิธีใช้งาน

1. เข้าสู่ระบบ เลือกร้าน แล้วเปิดแท็บ **บทสนทนาและสถิติ** หรือ `/app/shops/{shopId}/conversations`
2. ดูยอดภาพรวมทั้งร้าน ค้นด้วยชื่อลูกค้าหรือรหัสลูกค้า และกรองช่องทาง สถานะห้อง หรือสถานะบอท แล้วกด **ค้นหา**; กด **ล้าง** เพื่อกลับมาดูทั้งหมด
3. รายการเรียงตามการอัปเดตล่าสุด หน้าละ 20 ห้อง พร้อมข้อความล่าสุด จำนวนข้อความ และสถานะ
4. เลือกห้องเพื่ออ่านประวัติ เริ่มจากหน้าข้อความล่าสุด หน้าละ 50 ข้อความ ภายในหน้าเรียงเก่าไปใหม่ ใช้ **ข้อความเก่ากว่า/ใหม่กว่า** เพื่ออ่านประวัติทั้งหมด
5. กด **รีเฟรชข้อมูล** เพื่อโหลดใหม่ทันที รวมถึงลองอีกครั้งเมื่อโหลดผิดพลาด ระบบตรวจข้อมูลใหม่ทุก 15 วินาทีเมื่อเปิดหน้านี้และแท็บเบราว์เซอร์มองเห็นอยู่

ข้อความแสดงเป็น text ไม่แปล HTML และเวลาที่แสดงเป็นเวลาไทย เจ้าของร้านและสมาชิก role `agent` อ่านได้เฉพาะร้านที่มีสิทธิ์ คำตอบ API จากหน้าหรือร้านเก่าจะไม่ทับร้านปัจจุบัน การออกจากหน้า/ออกจากระบบจะยกเลิกคำขอและหยุดการตรวจข้อมูล

## นิยามสถิติ

สถิติเป็นยอดทั้งหมดของร้านตั้งแต่เริ่มใช้งาน ไม่ใช่ยอดเฉพาะหน้าที่โหลด และไม่เปลี่ยนตามตัวกรองรายการห้อง

| ตัวเลข | ความหมาย |
|---|---|
| บทสนทนาทั้งหมด | จำนวนแถวใน conversations ของร้าน ทั้ง LINE และเว็บ |
| เปิด/ปิด | จำนวนห้องที่อยู่ใน status open/closed ปัจจุบัน |
| บอทเปิดทำงาน/พักบอท/ส่งต่อแอดมินปัจจุบัน | จำนวนห้องใน bot_mode active/paused/human ตามลำดับ รวมทั้งห้องเปิดและปิด ไม่ใช่จำนวนครั้งส่งต่อสะสม |
| ข้อความทั้งหมด | จำนวนแถวใน messages ของร้าน รวม customer/assistant/agent/system |
| ข้อความจากแอดมิน | จำนวนข้อความ role agent ที่บันทึกแล้ว ไม่ใช่หลักฐานว่าส่งถึง LINE |
| ห้อง LINE/เว็บ และข้อความแต่ละ role | ยอดแยกตาม channel และ role ไม่ JOIN จนจำนวนถูกคูณ |

ข้อมูลจาก LINE Simulator และข้อมูลตัวอย่างที่บันทึกในฐานข้อมูลนับรวมด้วย ช่องทาง LINE จึงไม่ได้หมายความว่าทุกข้อความมาจากบัญชี LINE จริง ข้อความบอทที่ส่งผ่าน LINE ล้มเหลวไม่ถูกบันทึกเป็นข้อความผู้ช่วยตาม worker เดิม

## API

- `GET /api/v1/shops/{shopId}/statistics` คืน `{ data: { ...counts, generated_at } }` ใช้ Bearer session และตรวจสมาชิกของร้าน
- `GET /api/v1/shops/{shopId}/conversations` รองรับ `limit` (1–100), `offset`, `search` (ไม่เกิน 200 ตัวอักษร), `channel` (line/web), `status` (open/closed), `bot_mode` (active/paused/human)
- `search` ค้นชื่อลูกค้า/รหัสลูกค้าแบบข้อความตรงตัว ไม่ใช้ `%`/`_` เป็น wildcard; กรองใน SQL ก่อนนับ `meta.total` และแบ่งหน้า
- รายการห้องเพิ่ม `message_count` และ `last_message` (null เมื่อยังไม่มีข้อความ)
- `GET /api/v1/shops/{shopId}/conversations/{conversationId}` อ่านสถานะห้องล่าสุด
- `GET /api/v1/shops/{shopId}/conversations/{conversationId}/messages?limit=50&offset=0` อ่านข้อความเรียง created_at แล้ว id แบบคงที่ตาม PostgreSQL ของ master; เมื่อเวลาเท่ากันจะเรียงตาม id ไม่ใช่ลำดับ INSERT และไม่ใช้ rowid/ctid
- query ที่ไม่รู้จัก ค่าซ้ำ หรือ filter ไม่ถูกต้อง ตอบ 400; ไม่มี session ตอบ 401; ข้ามร้านหรือผสมรหัสห้องอีกร้านตอบ 404

## ขอบเขตและการตรวจ

- หน้านี้อ่านประวัติ/สถานะและสถิติเท่านั้น ปุ่มรับช่วง พิมพ์ตอบ และ Pause/Resume อยู่ในงานข้อ 10 ไม่แสดงปุ่มที่บันทึกข้อความแต่ยังไม่ส่งจริง
- `tests/conversation-api.test.js`: ตรวจยอดที่ทราบแน่นอน ห้องว่าง แยกร้าน กรองก่อนแบ่งหน้ามากกว่า 100 ห้อง ลำดับข้อความ และ signed webhook ที่ใช้ตัวส่ง LINE จำลอง
- `tests/conversation-dashboard.test.js`: ใช้ component/controller จริงกับ HTTP API และ PostgreSQL schema ชั่วคราว ตรวจค้นหา/แบ่งหน้า XSS เปิดใหม่ซ้ำ สลับร้านระหว่างรอ API ล้มเหลว/401 และ polling/visibility
- ชุดทดสอบทั้งสองไฟล์ใช้ `integration/postgresql-fixture.js` และ migrations เดียวกับ master ต้องตั้ง `TEST_DATABASE_URL` เป็นฐาน `chatbot_test` บน loopback โดยแยกจาก runtime; ลงทะเบียนใน `npm run test:runtime` ซึ่ง CI เรียกจริง ไม่มีการ skip หรือใช้ SQLite adapter
- การทดสอบข้างต้นไม่ใช่การส่งข้อความกับบัญชี LINE จริง และ DOM integration ไม่ใช่การตรวจภาพหน้าจอด้วยเบราว์เซอร์จริง
- ตรวจภาพแยกด้วย Chrome บน production build และฐานข้อมูลทดสอบที่พอร์ต 3109 แล้ว ทั้งจอปกติและมือถือ 390px: เลือกห้องอ่านประวัติได้ ตัวเลขตรงกับ fixture และเนื้อหาไม่ล้นแนวนอน ดูผลตรวจ/ข้อจำกัดใน `AI_CHECKPOINT.md`
